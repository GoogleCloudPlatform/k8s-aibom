## Steady state, and a fixture lesson

The first window ran unattended for 10.5 hours (03:32–14:03) with the
three walk Deployments. In that window the controller reconciled
Deployments 7,373 times, wrote AIBOM status 3,334 times with 698
`409` conflicts (all requeued and resolved), had 0 reconcile errors,
0 sink or status-persist failures, and averaged 2.8 mCPU
(104.5 cpu-s) at 45 Mi RSS / 29 Mi working set. That is **not** steady
state: the two pending fixtures were pinned with `nodeName` to a node
that does not exist, and Kubernetes pod garbage collection deletes
such pods, so the ReplicaSets recreated them every 20–40 s (verified
with the controller uninstalled: a probe pod changed name within
60 s). Every recreation is a pod event, a reconcile, and a fast-path
status write that touches only `lastReconciled` — `inputHash`,
`bomHash` and the document's scrape timestamp stayed constant across
pod recreations (sampled every 20 s). Earlier walks' "pinned to a
non-existent node" fixtures should be read with this in mind; from now
on pending fixtures use a `nodeSelector` no node satisfies.

Controlled comparison, same cluster, one vLLM Deployment each, eight
minutes per window, counters as deltas:

| Window | Build | Fixture | Deployment reconciles | status PUT 200 / 409 | GET 200 | CPU |
|---|---|---|---|---|---|---|
| A | v1.7.0-rc.1 | `nodeSelector` pin (no churn) | **0** | **0 / 0** | 14 (1.75/min) | 1.28 cpu-s, **2.6 mCPU** |
| B | v1.7.0-rc.1 | `nodeName` pin (PodGC churn) | 55 | 43 / 12 | 111 | 1.56 cpu-s, 3.2 mCPU |
| C | v1.6.2 | `nodeName` pin (PodGC churn) | 58 | 45 / 13 | 118 | 1.33 cpu-s, 2.6 mCPU |

Window A is the release's steady state: no writes, 1.75 requests per
minute with one third-party CRD (KServe) present, in line with v1.6.0-rc.1's
3.26/min with three present. Windows B and C show that the
write-per-reconcile on the unchanged-input fast path is the same in v1.6.2 and v1.7.0-rc.1, so it is pre-existing behaviour and not a regression of this release; it is
tracked for 1.8 as a rate-limit on the `lastReconciled` touch
(#409).
